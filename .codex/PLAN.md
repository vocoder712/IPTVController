# IPTVController 阶段计划

## 第一阶段：LAN2 开关框架与容器能力验证（已完成）

## 目标

第一阶段只验证容器内服务控制主系统 LAN2（`eth1`）的能力，并提供一个最小 H5 开关页面。暂不实现计划任务、HTTPS、Android、远程访问、认证、IPTV VLAN/组播分析或厂商网页 API。

## 已知环境

- SG631Z，ARMv7 Linux 4.19；根文件系统只读。
- OpenWrt 运行在 `ufw` LXC 中，`lxc.net.0.type = none`，与主系统共享 network/user namespace。
- 容器可见 `eth0`-`eth3`，LAN2 为 `eth1`，并具备 `CAP_NET_ADMIN`。
- 持久应用目录：`/opt/cu/apps/apps/opt/apps/`。
- 容器启动脚本目录：`/opt/cu/apps/apps/root/scripts/`。
- 服务首版监听 `192.168.1.1:8088`，不启用 HTTPS。

## 首版实现

- Go 标准库单文件服务，内嵌 H5 页面。
- `GET /api/v1/status`、`POST /api/v1/port`、`GET /healthz`。
- `PortController` 抽象；开发默认模拟执行器，设备上设置 `IPTV_CONTROL_REAL=1` 后调用 `/bin/ip`。
- 启动时检查 UID、`eth1`、能力和工具；定期读取接口状态并报告厂商回拉。
- 状态和最后一次手动状态使用原子 JSON 保存；日志优先写入易失目录。
- 提供 `deploy/bootshell.sh` 固定启动入口模板，使用容器路径
  `/opt/apps/iptv-control`；真实控制默认禁用。

## 验证分层

1. 只读检查 namespace、能力、`eth1` 和 `/bin/ip`。
2. 无损 `ip link set eth1 up` 检查；若原状态为 down 不改变它。
3. 受控 down/up 测试仅由显式命令触发，当前不自动执行。
4. 观察 1-5 分钟，记录厂商进程是否回拉接口。

## 第一阶段完成结论

- 固定 `bootshell.sh` 经真实重启验证，可启动 OpenWrt/LXC 容器进程。
- 容器服务必须使用 `/sbin/ip`，不能使用主系统视角的 `/bin/ip`。
- 真实模式 HTTP API 已由用户实机验证，可正确开启和关闭 LAN2。
- `carrier=1` 表示机顶盒已开机且 LAN2 已启用；机顶盒关机或端口关闭时为 0。
- Telnet 只用于主系统诊断，不能用 Telnet 启动的进程替代容器部署。

## 第二阶段：智能限时

### 目标

通过 `carrier` 判断是否正在看电视，累计连续观看时间。达到限时后进入柔性干预：
每 60 秒周期中保持 LAN2 接通 57 秒、关闭 3 秒，促使儿童主动关闭电视。

### 默认参数

- 载波查询间隔：30 秒。
- 连续观看限时：20 分钟，可配置。
- 干预周期：60 秒。
- 每周期断网：3 秒；接通 57 秒。

### 状态机

1. `idle`：`carrier=0`，未观看；清零连续观看计时。
2. `watching`：`carrier=1`，每 30 秒累计连续观看时长。
3. `intervention`：达到限时后，循环执行 57 秒 up、3 秒 down。
4. 干预期间发现机顶盒关闭（在接口 up 的观察窗口内 `carrier=0`）后退出干预，
   恢复接口为 up 并清零计时。

不能把主动执行 down 后产生的 `carrier=0` 误判为用户已关电视；判断退出只能
使用接口已恢复 up 后的载波采样。

### 实现任务

1. 增加可注入时钟、ticker 和 `PortController` 的限时状态机，先完成单元测试。
2. 增加配置项并校验范围：查询间隔、观看限时、干预周期、断网时长。
3. 原子持久化状态：连续观看起点、当前阶段、最后控制动作及错误；重启后安全恢复。
4. 增加状态 API 字段和 H5 展示：模式、已观看时长、剩余时间、下次动作、
   干预状态；提供启用/停用及重置计时控制。
5. 明确手动开关与自动限时的优先级，避免控制循环与页面操作互相竞争。
6. 设备模拟测试后再进行实机验证：短参数加速测试、退出条件、重启恢复、
   连续运行和厂商回拉观察。

### 安全约束

- 服务退出、重启或状态机异常时必须尽力保持 LAN2 为 up。
- 每次 down 必须有独立的延迟 up 兜底，不能只依赖同一控制循环恢复。
- 自动功能默认关闭，配置完成并通过模拟验证后才在设备上显式启用。
- 当前 HTTP 服务无认证，只允许暴露在可信管理网。
