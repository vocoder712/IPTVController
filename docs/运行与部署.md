# 运行模式与部署

本文说明 IPTVController 的三种运行方式，以及从本地开发安全切换到设备
实际控制的步骤。

## 模式选择

程序只通过一个开关区分模拟和实际控制：

```text
IPTV_CONTROL_REAL=1      实际模式
未设置或不是 1           模拟模式
```

该值在进程启动时读取。修改环境变量后，必须重启服务才会切换模式。

### 本地开发模式

运行在开发机上，`IPTV_CONTROL_REAL` 不设置。

- 用于开发页面、HTTP handler 和客户端调用。
- 不要求 Linux、root、`/sys` 或 `/bin/ip`。
- 页面按钮只更新进程内存中的模拟状态。
- `oper_state`、`carrier` 和 `capability_check` 会表明当前是模拟结果。
- 服务重启后模拟状态丢失。

### 设备模拟模式

ARMv7 程序已经复制到 SG631Z，但 `IPTV_CONTROL_REAL` 仍不设置。

- 用于验证二进制能否运行、8088 是否正确监听、H5/API 是否可访问、启动脚本
  和日志路径是否正确。
- 即使接口名设置为 `eth1`，程序也不会读取或修改 LAN2。
- 这是首次部署时必须先经过的安全验证阶段。

### 设备实际模式

ARMv7 程序运行在设备上，并在启动前设置 `IPTV_CONTROL_REAL=1`。

- 状态 API 从 `/sys/class/net/eth1` 读取 flags 和 operstate，从厂商 DBus
  `com.cuc.igd1.NetworkInfo.LAN2Status` 读取真实 LAN2 物理链路。
- 开关 API 调用配置的 `ip` 命令；SG631Z 容器部署使用
  `/sbin/ip link set dev eth1 up|down`。
- 必须使用 root 运行。
- 操作会真实中断或恢复电视业务。

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `IPTV_CONTROL_REAL` | 未设置 | 只有精确值 `1` 启用实际控制 |
| `IPTV_CONTROL_ADDR` | `:8088` | HTTP 监听地址 |
| `IPTV_CONTROL_INTERFACE` | `eth1` | 实际模式控制的接口 |
| `IPTV_CONTROL_IP` | `/bin/ip` | `ip` 命令路径；SG631Z 容器实际使用 `/sbin/ip` |
| `IPTV_CONTROL_DBUS_SEND` | `/usr/bin/dbus-send` | SG631Z LAN2 状态查询命令 |
| `IPTV_CONTROL_STATE_FILE` | 未设置 | 智能限时持久日志；设备使用 `/opt/apps/iptv-control/state/state.log` |
| `IPTV_LIMITER_DOWN_DURATION` | `6s` | 默认阻断时长，必须为 1–25 整数秒 |

设备上建议固定使用：

```sh
export IPTV_CONTROL_ADDR="192.168.1.1:8088"
export IPTV_CONTROL_INTERFACE="eth1"
export IPTV_CONTROL_IP="/sbin/ip"
export IPTV_CONTROL_DBUS_SEND="/usr/bin/dbus-send"
export IPTV_CONTROL_STATE_FILE="/opt/apps/iptv-control/state/state.log"
```

不要将监听地址改成公网地址。当前版本没有认证。

## 1. 本地开发

PowerShell：

```powershell
$env:GOCACHE = "$PWD/.cache/go-build"
$env:GOMODCACHE = "$PWD/.cache/go-mod"
$env:GOPATH = "$PWD/.cache/gopath"

Remove-Item Env:IPTV_CONTROL_REAL -ErrorAction SilentlyContinue
$env:IPTV_CONTROL_ADDR = "127.0.0.1:8088"
go test ./...
go run ./cmd/iptv-control
```

浏览器访问：

```text
http://127.0.0.1:8088/
```

另一个 PowerShell 窗口可以验证 API：

```powershell
curl.exe --silent http://127.0.0.1:8088/healthz
curl.exe --silent http://127.0.0.1:8088/api/v1/status
curl.exe --silent -X POST `
  -H "Content-Type: application/json" `
  -d '{"enabled":true}' `
  http://127.0.0.1:8088/api/v1/port
```

预期特征：

- `/healthz` 中 `real_control` 为 `false`；
- `/api/v1/status` 中 `capability_check` 为 `simulation`；
- `oper_state` 和 `carrier` 为 `simulated`；
- 点击关闭不会造成电视断连。

## 2. 构建 ARMv7 二进制

PowerShell：

```powershell
$env:GOCACHE = "$PWD/.cache/go-build"
$env:GOMODCACHE = "$PWD/.cache/go-mod"
$env:GOPATH = "$PWD/.cache/gopath"
$env:GOOS = "linux"
$env:GOARCH = "arm"
$env:GOARM = "5"
$env:CGO_ENABLED = "0"
go build -trimpath -ldflags="-s -w" -o dist/iptv-control ./cmd/iptv-control
```

SG631Z 的系统架构为 `armv7l`，但实测 `/proc/cpuinfo` 的 Features 不包含
`vfp` 或 `vfpv3`。因此必须使用 `GOARM=5` 生成软浮点兼容二进制。
`GOARM=7` 虽能成功编译，但会在设备上以 `Illegal instruction` 退出。

将 ARMv7 二进制和单一启动入口模板通过已有的文件传输方式复制到设备：

```text
dist/iptv-control
deploy/bootshell.sh
```

目标位置：

```text
/opt/cu/apps/apps/opt/apps/iptv-control/iptv-control
/opt/cu/apps/apps/root/scripts/bootshell.sh
```

设备上设置执行权限：

```sh
chmod 755 /opt/cu/apps/apps/opt/apps/iptv-control/iptv-control
chmod 755 /opt/cu/apps/apps/root/scripts/bootshell.sh
```

## 3. 首次设备部署：先使用模拟模式

确认 `bootshell.sh` 中的这一行仍保持注释：

```sh
# export IPTV_CONTROL_REAL=1
```

手动启动验证时，明确清除可能继承的真实模式变量：

```sh
unset IPTV_CONTROL_REAL
export IPTV_CONTROL_ADDR="192.168.1.1:8088"
export IPTV_CONTROL_INTERFACE="eth1"
/opt/cu/apps/apps/opt/apps/iptv-control/iptv-control \
  >/var/log/iptv-control.log 2>&1 &
echo $!
```

检查进程和日志：

```sh
ps | grep '[i]ptv-control'
tail -n 50 /var/log/iptv-control.log
```

从管理电脑验证：

```powershell
curl.exe --max-time 5 http://192.168.1.1:8088/healthz
curl.exe --max-time 5 http://192.168.1.1:8088/api/v1/status
```

只有同时满足以下条件，才进入实际模式：

- 两个 HTTP 请求均在 5 秒内返回；
- `real_control` 为 `false`；
- 页面可以打开；
- 模拟开关后电视业务没有变化；
- 日志中没有持续报错。

如果 8088 只能建立 TCP 连接但 HTTP 没有响应，不要启用实际模式。先检查是否
已有旧进程占用端口、当前运行的二进制是否为最新版以及日志内容。

## 4. 切换到设备实际模式

切换前确认：

```sh
id
test -d /sys/class/net/eth1
test -x /sbin/ip
test -x /usr/bin/dbus-send
test -S /var/run/dbus/system_bus_socket
/sbin/ip link show dev eth1
```

必须确认当前管理会话走 LAN3 或其他管理链路。首次实际验证应有人观察电视，
并准备好 `docs/基本信息.md` 中的延迟恢复兜底方法。

停止模拟进程后，以实际模式启动：

```sh
export IPTV_CONTROL_REAL=1
export IPTV_CONTROL_ADDR="192.168.1.1:8088"
export IPTV_CONTROL_INTERFACE="eth1"
export IPTV_CONTROL_IP="/sbin/ip"
export IPTV_CONTROL_DBUS_SEND="/usr/bin/dbus-send"
/opt/cu/apps/apps/opt/apps/iptv-control/iptv-control \
  >/var/log/iptv-control.log 2>&1 &
echo $!
```

先只查询，不要立即关闭：

```powershell
curl.exe --max-time 5 http://192.168.1.1:8088/healthz
curl.exe --max-time 5 http://192.168.1.1:8088/api/v1/status
```

预期：

- `real_control` 为 `true`；
- `interface` 为 `eth1`；
- 正常链路下 `admin_up=true`、`carrier=1`，且
  `carrier_source=dbus_lan2_status`。`oper_state` 是驱动诊断值，本固件可能
  显示 `unknown`，不用于智能限时判断。

确认无误后才执行真实开关：

```powershell
# 真实关闭 LAN2
curl.exe --max-time 5 -X POST `
  -H "Content-Type: application/json" `
  -d '{"enabled":false}' `
  http://192.168.1.1:8088/api/v1/port

# 真实开启 LAN2
curl.exe --max-time 5 -X POST `
  -H "Content-Type: application/json" `
  -d '{"enabled":true}' `
  http://192.168.1.1:8088/api/v1/port
```

注意：当前 API 只执行单次开或关，没有内置“5 秒后自动恢复”。短时断连测试
应继续使用 `docs/基本信息.md` 中已验证的 `nohup` 延迟恢复命令，不能只依赖
两次 HTTP 请求。

## 5. 配置设备启动入口

仓库中的 `deploy/bootshell.sh` 是 OpenWrt 固定启动入口模板，默认是设备模拟模式。
它必须使用容器路径 `/opt/apps/iptv-control`，不能改回主系统路径
`/opt/cu/apps/apps/opt/apps/iptv-control`：

```sh
# export IPTV_CONTROL_REAL=1
```

设备模拟验证完成后，如决定让开机服务实际控制 LAN2，才取消该行注释：

```sh
export IPTV_CONTROL_REAL=1
```

启动入口位于持久目录，但日志 `/var/log/iptv-control.log` 是易失的，设备
重启后日志可能丢失。不要在设备有限的持久存储上记录大量日志。

修改开机配置后应再次检查脚本内容和权限。不要仅因为脚本已复制就认为服务
已经运行；必须在重启后重新验证进程、日志、`/healthz` 和状态 API。

## API 摘要

### 查询健康状态

```http
GET /healthz
```

重点查看 `ok` 和 `real_control`。

### 查询端口状态

```http
GET /api/v1/status
```

实际模式重点查看：

- `admin_up`：接口管理状态；
- `oper_state`：Linux 驱动运行状态，仅作诊断；
- `carrier`：厂商 DBus 返回的物理链路，`1` 表示有载波；
- `carrier_source`：实际设备应为 `dbus_lan2_status`；
- `last_error`：最近一次状态读取或控制错误。

### 设置端口状态

```http
POST /api/v1/port
Content-Type: application/json

{"enabled":true}
```

`true` 表示开启，`false` 表示关闭。在模拟模式中只改变内存状态；在实际模式
中会真实执行 `ip link`。

### 设置智能限时

```http
POST /api/v1/limiter
Content-Type: application/json

{"enabled":true,"max_watch_minutes":20,"block_seconds":6}
```

- `max_watch_minutes` 范围为 1–1440；
- `block_seconds` 是每个 60 秒干预周期中的阻断时长，范围为 1–25 整数秒；
- 省略 `block_seconds` 时保留当前值，用于兼容旧客户端；
- 保存任一设置都会清除本次计时并从下一次有效载波采样重新开始。
