## 光猫系统概况

### CPU 与 Go 构建兼容性

- 系统报告 `armv7l`，CPU 为 ARMv7 Processor rev 1。
- `/proc/cpuinfo` 的 Features 不包含 `vfp` 或 `vfpv3`。
- Go 交叉构建必须设置 `GOARM=5`，使用软浮点兼容代码。
- `GOARM=7` 二进制虽然能编译成功，但在设备启动时会立即报告
  `Illegal instruction`。

## LAN2 口可靠开关方法

### 已确认的接口映射

- LAN2 对应 Linux 接口 `eth1`。
- 应通过 LAN3 或其他管理链路登录光猫，避免关闭 LAN2 后同时中断管理会话。
- 普通用户登录 Telnet 后，需要执行 `su` 切换为超级管理员；实际开关接口需要 root 权限。

### 标准开关命令

关闭 LAN2：

```sh
ip link set dev eth1 down
```

开启 LAN2：

```sh
ip link set dev eth1 up
```

命令执行后必须读取实际链路状态，不应只根据命令退出状态判断：

```sh
ip link show dev eth1
cat /sys/class/net/eth1/operstate
dbus-send --system --type=method_call --print-reply --reply-timeout=3000 \
  --dest=com.cuc.igd1 /com/cuc/igd1/Info/Network \
  org.freedesktop.DBus.Properties.Get \
  string:com.cuc.igd1.NetworkInfo string:LAN2Status
```

正常开启且网线、对端设备均正常时，应看到：

- `ip link` 包含 `UP`；
- DBus `LAN2Status` 返回 `variant byte 1`。

关闭后应看到 `state DOWN`，且接口标志中不再包含 `UP`。本固件启动后 sysfs
的 `carrier` 和 `operstate` 曾出现错误初态，不能据此判断机顶盒是否开机。

### 短时断连测试

进行短时断连时，应先启动一个独立的延迟恢复命令作为兜底，再执行正式的
`down`、等待和 `up`。下面的命令会断开 LAN2 5 秒，并在 12 秒后再次强制
开启一次 LAN2，防止控制会话异常导致端口长时间关闭：

```sh
nohup sh -c 'sleep 12; ip link set dev eth1 up' >/dev/null 2>&1 &
ip link set dev eth1 down
echo "DOWN_EPOCH=$(date +%s)"
sleep 5
ip link set dev eth1 up
echo "UP_EPOCH=$(date +%s)"
sleep 2
ip link show dev eth1
echo "OPER=$(cat /sys/class/net/eth1/operstate)"
echo "CARRIER=$(cat /sys/class/net/eth1/carrier)"
```

注意：

- 延迟恢复命令必须在 `down` 之前启动，并使用 `nohup` 脱离 Telnet 会话。
- `UP_EPOCH - DOWN_EPOCH` 应等于计划的断连秒数。
- 恢复后应同时确认 `operstate=up` 和 `carrier=1`。
- 可继续采样 `/sys/class/net/eth1/statistics/rx_bytes` 与 `tx_bytes`；计数持续
  增长表示链路恢复后已有业务流量。
- 永久关闭 LAN2 时不要使用上述延迟恢复兜底，直接使用标准关闭命令。

- OpenWrt/LXC 容器中的 `ip` 实际路径为 `/sbin/ip`；主系统 Telnet 中的
  `/bin/ip` 不能直接套用到容器服务配置。
- 固定 `bootshell.sh` 已配置 `IPTV_CONTROL_REAL=1` 和
  `IPTV_CONTROL_IP=/sbin/ip`，经重启后以容器进程运行。
- 用户通过真实模式 API 手动验证，LAN2 可以正确开启和关闭。
- 厂商 DBus `LAN2Status` 已完成开关机 A/B 验证：机顶盒开机且 LAN2 启用
  时为 1，机顶盒关机时为 0；主系统与 IPTV 容器查询一致。
- Linux sysfs `carrier` 在本次重启后曾在物理端口未连接时错误返回 1，
  后续物理事件才恢复更新，因此不再作为智能限时状态源。
- Telnet 主系统进程仅用于诊断，不能作为长期容器部署方式或容器运行验收。
